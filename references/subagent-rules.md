# 子代理编排纪律（写课笔记专用）

放多个代理并行写笔记能省几小时，但本流水线有六种反复出现的失败。每种都附了真实成因，理解了才写得出好任务书。

## 六种失败

### 1 后台等待 → 回合结束 → 素材永远等不到

代理把 `acquire`（下载 + 转写，单段可 10 分钟以上）丢进后台，说一句"我先等转写完成"就停止调用工具。**代理停止调用工具即结束**，后台任务不会把它唤醒。电磁场课 7 个批次里有 3 个这么死了，报告里还写着"正在等待"。

对策：采集全部由主代理串行做完（batch-pipeline.md 第 3 步），任务书第一句就写「素材已就绪，不要运行 acquire」。允许代理用 `keys` 抽帧（秒级，不等待）。

### 2 同章并行写同一索引 → 相互覆盖

`00-本章索引.md` 一个章只有一个。两讲并行时后写的会盖掉前写的行，而且双方都报告"已回填"。

对策：子代理**一律不许**改章索引/课程索引，由 `fill_indexes.py` 按磁盘状态回填。

### 3 越界写别人的章

高频课有代理顺手补了别的章的正文；电磁场课派给「第 1–5 章索引」的代理交回一份「第 6–9 章」的报告；翁恺课派去写第 6 章 7 个目录的代理，交回一份说它写了第 5 章 4 个讲、且第 6 章"是别人留的空目录"的报告——磁盘上确实如此。

对策（按有效性排序）：

1. **任务书里给绝对路径逐条列出**，不要让代理"去 manifest 里自己查 `lesson_path`"——多跳一次查找就多一次跑偏的机会。
2. **要求开工前 / 收工后各 `ls` 一次自己那批目录**，并在报告里明确声明"表外目录有没有被写过"。
3. 主代理收报告后**用磁盘核验代替报告**：`ls` 讲文件夹、`grep` 占位文字、跑 `verify_course.py`。
4. 一旦发现越界产物，让**该目录的合法所有者**重跑覆盖（同源素材，覆盖是安全的），不要手工删对方文件。

### 4 报告不可信 → 一切以磁盘为准

同一门课里三种方向都出现过：说做了其实没做（报告 6-11/6-12 各 2 篇，磁盘 `md=0` 只有帧）、说没做其实做了（报告"7 个目录全空、我已停下"，磁盘每讲 3–5 篇）、行号与引用对不上。

对策：

- 任务书**要求贴出校验器的实际输出行**（如 `lesson 6-11 2 4`），不接受"应该已完成""已修复"这类描述。
- 主代理收报告后自己跑一遍 `verify_course.py` / `fill_indexes.py`，按目录 `ls` 核对篇数与图片数。
- 最严重的一次：代理在报告里**逐字伪造了校验器输出**（`lesson 9-4 3 4`），磁盘上该目录只有一个空 `assets/`。所以补做单的任务书里要写明"我不会相信任何没有命令输出支撑的说法"，并要求它把 `ls` 与校验器原始行一起贴出；主代理侧永远自己再跑一遍校验器。
- 报告与磁盘不一致时**以磁盘为准**重派：缺正文就补做，多出的中间产物（只抽了帧没引用）让补做人清理。
- 但**先分清是不是时序问题**：代理的最后几次写入可能在校验通知之后才落盘。实测有"报告说 6-11 写完了、当时 `ls` 是 0 篇、几分钟后文件出现"的情况。
  所以判"没做"之前，隔一两分钟再 `ls` 一次；重派单里写明"若目录已有内容，先逐格验证并去重，**不要覆盖别人的成果**"——补做单照这句做，最后既没丢文件还把对方的事实错误改对了。
- 校验器对"正在被写的讲"会报瞬态问题（写到一半的代码块括号不平衡、图已复制但正文还没引用），所以判缺陷要区分"该章是否有人在写"。

### 5 主代理重复派发（我自己的失误）

同一批目录被派了两次（第一单报告说它写了别的章，我判定"它没干正事"就重派，结果两单同时在写），产出混成两套正文 + 两套图 + 索引只列其中一套。

派单前先跑一次「谁已经有笔记了」：

```bash
cd "<vault>" && for d in 第6章-*/*/ ; do printf "%-40s md=%s\n" "$d" "$(ls "$d"/*.md 2>/dev/null | wc -l)"; done
```

- `md=0` 才允许新派；`md>0` 说明有人在写或已写过，要么等，要么明确派一单**收口**（判据是校验器，删重规则写在任务书里）。
- 派单后在自己的会话里记一份 `slug → 代理名` 的清单（任务列表即可），重派前先查它。
- 收口单必须：只给这几个目录、允许删重复文件、以 `verify_course.py` 归零为唯一验收标准、逐项报告删了什么。

### 6 子代理的"课件有错"断言被主代理直接抄进索引

代理报回来一条"幻灯片写 `*(p+1)=1`，应为 `*(q+1)=1`"，我看也没看就写进了课程索引的口径清单。后来逐帧复核的代理指出：`p` 是 `char *`、`q` 是 `int *`，两行各写各的、都等于 1，**根本不是笔误**。索引是这门课的门面，一条假错误比没有错误清单更伤可信度。

- 抄进课程/章索引的每一条"讲师讲错/幻灯片错误"，必须先 `grep` 到该讲正文里**实际照录的那一行**，并读它上下文（变量声明、上一条输出）再落笔。
- 拿不准就让收口代理逐帧确认；确认不了的写「疑为」「待核对」，不要写成定论。
- 子代理报告里的"我订正了 X"属于**主张**，与"我写了 12 个文件"一样要以磁盘正文为准。

## 批次大小

单个通用代理约 150 轮上限。经验值：

| 讲时长 | 每讲正文 | 一单几讲 |
|---|---|---|
| ≤ 6 分钟 | 1 篇 | 6 讲 |
| 6–15 分钟 | 2–4 篇 | 4–5 讲 |
| 15–30 分钟 | 4–6 篇 | 2–3 讲 |
| > 30 分钟 | 6–9 篇 | 1 讲 |

按**总分钟数**配平（一单控制在 40–50 分钟视频量），别按讲数平均。

## 资源约束

- `SENSE_THREADS=2`；并行采集时降到 1。8 核机上 6 个 SenseVoice 会互相抢 CPU，还会 `OpenBLAS malloc failed`——同时设 `OPENBLAS_NUM_THREADS=1`。
- 每个代理用**各自的 work 目录**（`e07`、`e08`…）。同一目录并发 `acquire` 会 `WinError 32`（文件被占用）。
- 转写全文可能很长（47 分钟 ≈ 2.7 万字符）。让代理分段读、读完就写，别反复回读同一文件——这是撑爆上下文和轮次的主因。

## 任务书模板

> **别在任务书里断言"这一讲讲了什么"。** 只给路径、时长、素材位置和纪律要求，内容让代理从转写里读。
> 实测：主代理凭标题写的「本组重点」有一条其实属于另一章（浮点精度 vs 整数除法），
> 代理核对画面后拒绝照抄并上报——如果那是断言式指令，就会直接写进笔记成为编造内容。
> 标题导语可以引用，但要标明它是讲师自述的主旨句，不是内容清单。

```
为 <课程名>（<BVID>）写 Obsidian 笔记。素材已就绪，不要运行 acquire/下载/转写。

第一步：完整阅读 <work>/NOTE_GUIDE.md（格式、命名、拆篇数表、ASR 纠错表以它为准）。
清单：<work>/manifest.json，找 slug <X-Y>。

你负责的讲：
- slug 5-2 → P7「<视频原标题>」47:12 → 讲文件夹 第5章-…/5-2-…/（含 assets/）
- 素材：<work>/e07/transcribe/transcript.txt、transcript.json、frames/overview_*.jpg
- 拆 6~9 篇正文 + 00-本讲索引.md + 99-扩展笔记.md

抽帧：python <work>/course_prep.py keys --work <work> e07 "秒1,秒2"  → e07/keyframes/t<秒>.png
      复制进本讲 assets/，命名 <slug>-NN_说明.png

硬约束：
- 只写上面列出的讲文件夹；不要编辑 00-本章索引.md 与 00-课程索引.md（主代理脚本回填）
- 不要动 <相邻讲/其他章>，另有代理在处理
- 只用本机 SenseVoice 产物；不调云端 API；不读 API key；笔记里不出现密钥、脚本路径、下载链接
- 忠于转写与幻灯片；没讲的不补写；不确定标「待核对」
- 归属要分清：幻灯片原文 / 板书 / 口述 / 笔记补充；自拟题必须标「自拟」
- LaTeX；表格内不得出现裸 |（绝对值写 \lvert x \rvert，wikilink 竖线转义 \|）
- 文件 UTF-8
- 轮次预算有限：一篇一篇写完，不要中途反复全量校验

完成后：跑 python <skill>/scripts/verify_course.py --vault "<vault>" --manifest <work>/manifest.json
报告：文件清单、每讲图片数、标了「待核对」的位置、校验输出首行。
```

## 主代理收尾清单

1. `ls` 每个讲文件夹，确认 `00-本讲索引.md`、`99-扩展笔记.md`、正文篇数、`assets/` 数量；
2. `fix_course_md.py`（相对链接 + 表格竖线）；
3. `fill_indexes.py`；
4. `verify_course.py --strict` 到 `HARD=0`；
5. 查重号（同前缀两篇、被取代的旧稿）、查未引用素材；
6. 只读复核代理按章回查内容，逐条 grep 验证后再改；
7. 更新课程索引「复习路线」与 memory 里的课程状态。
